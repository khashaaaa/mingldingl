Four `react/*` rules are off on purpose, not by oversight.

`refs` (199 hits) fires on `.current` read during render. Every hit is an
`Animated.Value`/`SharedValue` held in a `useRef` — `GemTierBadge`, `Entering`, `HonourCase`,
`Lantern` — which is the documented React Native idiom for a value the UI thread animates and
React must not re-render on. The rule is right about React state and wrong about this.

`set-state-in-effect` (23) fires on effects that sync from a prop or an external subscription
(`useVfxLevel`'s `AccessibilityInfo` listener, `WorldProvider`'s clock). Those are exactly the
"synchronising with an external system" case the rule's own help text allows for, but it cannot
see the difference.

`immutability` and `purity` (7) fire on the same Animated patterns.

Turn any of them back on with a sweep to fix the real hits, not one at a time — a rule left at
`warn` with 199 standing hits is a rule nobody reads.
